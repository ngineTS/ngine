Introduction

Who has ever worked in the applications world knows that an important amount of resources is spent on the core of the application instead of the business features.

Ngine is the promise of a robust and scalable core, that contains the essential necessary to an application. Therefore you can focus on your business implementation only and never spend resources on the rest again. This allows you to save costs, not only on development side, but on testing and management side as well. Maintenance becomes very light, however heavy your application is.

The framework can be divided in two parts:

1. The layout builder

An admin interface that allows you to build the global structure of your application (landing pages, navigation bars, trees, routing, menus…). You can manage the user access and permission of all sections and modify your structure at anytime with a maximum of flexibility.

2. The feature integration

Here is the power of Ngine. You develop your feature as you are used to with NestJS and Angular then you add it to the feature library. Once in the library, you can plug it anywhere in your application in two clicks without template integration! The biggest advantage is that you don't need to touch a single file of the core to implement a new feature so no risk to break other parts of the application. It results in less bugs and a better control on your code base.

The starter feature library contains:

  • a user authentication form
  • a user role management interface: to manage users and their role(s) within the application
  • a file management interface: to view and manage all the files uploaded
  • an analytic interface: to visualize the main metrics of your application (MAU, daily visits…)
  • a calendar: to publish information/events
  • other common features (text editor, media, simple shape, buttons, manageable list of items…)

You can imagine Ngine as a museum with an infinite number of rooms. All the hallways, the security, the room authorizations are defined, the Data related to the museum activity is collected and visualizable. The only thing pending is to decorate the rooms (build the features).

This is the perfect tool in a AI world because you can ask agents to build features independently from the rest of the application and insure it doesn't break it. Also, the quantity of code required to build an application with Ngine is significantly reduced which means if you use an AI agent to build your app, the token consumption will be much lower than with other frameworks.
